## What this repository is for

DraconDex is developed in a **private** repository. GitHub's REST API answers
`404` for a private repository to anyone without a token — and "anyone without
a token" is every install of the app and every visitor of the website. That
broke two things at once:

- the **in-app update check**, on both the Windows desktop build and the
  Android build, which treats any non-200 as "no update available" and so
  reported *"you are on the latest version"* no matter how many releases had
  shipped;
- the **download page** on the website, which builds its file list from the
  same API in the visitor's browser.

So every release is mirrored here, into a public repository that contains
nothing but releases. The mirror is what the apps and the website read.
Nothing is published here by hand.

## What lands here

Both of DraconDex's release trains are mirrored, keeping their original tags:

| Tag | Product | Assets |
|---|---|---|
| `vX.Y.Z` | Electron desktop app (Windows) | `DraconDex-Setup-<v>.exe` (installer), `DraconDex-Portable-<v>.exe` (single file), `DraconDex-<v>-win-x64.zip` (portable folder), `checksums-sha256.txt` |
| `flutter-vX.Y.Z` | Flutter Android app | `DraconDex-<v>-release.apk` (universal) plus one APK per ABI (`arm64-v8a`, `armeabi-v7a`, `x86_64`), `checksums-sha256.txt` |

The two version numbers are **independent** — the desktop app's `4.13.x` and
the Android app's `2.10.x` are unrelated, and either may be the most recently
published release. Pick by tag prefix, not by which release is on top.

> **A note on ordering.** GitHub sorts releases (and picks the "Latest" badge)
> by each release's `created_at`, which is the date of the *commit its tag
> points at* — not the date it was published. Every tag here is cut from the
> same branch head, so ordering in the API response is not meaningful. If you
> read this feed programmatically, **compare version numbers**; do not take the
> first entry. Getting this wrong is a real bug the apps shipped: `2.10.1`
> sorted below `2.9.0` and every 2.9 install was told it was up to date.

## Verifying a download

Every release carries a `checksums-sha256.txt` covering its own assets.

```bash
sha256sum -c checksums-sha256.txt --ignore-missing
```

```powershell
Get-FileHash .\DraconDex-Setup-4.13.2.exe -Algorithm SHA256
```

The Android APKs are signed with a permanent release certificate, so an
in-app update installs over an existing install. Its SHA-256 fingerprint is
`6b1b62e9ba2654a31ff0b4d41d1b53e4db5b0e940acda5fd2bff4f21c2dc97e8` and it will
not change; a build signed with anything else is not ours.

## How the mirror works

Everything below lives in the app repository, not here:

| Piece | Role |
|---|---|
| `.github/scripts/mirror-release.sh` | Reads a release's notes and assets from the app repo and re-publishes them here. Takes one tag, or `--all` to walk the whole history. |
| `mirror` job in `build-electron.yml` / `build-apk.yml` | Runs right after a release is published, uploading the very assets the build job produced. |
| `.github/workflows/mirror-releases.yml` | Manual lever — backfill everything, or re-mirror a single tag. |

Release notes are copied verbatim. Notes generated by GitHub link to compare
views and pull requests **inside the private repository**, so those links do
not open for the public; each mirrored release carries a line saying so rather
than leaving the links unexplained.
